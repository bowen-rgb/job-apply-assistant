# 二维码投递

招聘入口现在支持在当前窗口抓取岗位、按开始月份/专业方向/地点筛选，以及通过专用 Chrome 的 ChatGPT 辅助解释。详见[岗位抓取使用说明与限制](QR_CRAWLER.md)。

### 企业辨认、照片和批量移除

Inmind 收简历页面现在直接读取企业字段，识别为通用 CV 库，按企业业务匹配材料，点击后仅发送 CV，不生成动机信；实现及 REA 调查记录见[来源排查说明](SOURCE_INSPECTION.md)。

- 企业名称去掉已识别的招聘页前后缀，例如“Emploi groupe SNCF : Recrutement”显示“SNCF”；原网页标题及引文仍保留作证据。招聘系统域名不作为企业名。没有可靠名称时显示“企业待确认”，网址仅作辅助辨认。
- 打开或选择仍缺企业且需要补充识别的草稿时，自动发起该项只读识别（不投递），用于修复旧记录；已有可靠企业名称的项不因切换而重新分析。另一任务忙碌时保留错误和重试按钮。
- 点详情中的照片或左侧缩略图放大；支持缩放、滚动查看、Esc/关闭返回。
- 新导入照片重新编码为 PNG，保存在当前候选人的本地忽略目录 `qr-images/`，刷新后可查看。二维码图片不会自动发给 ChatGPT。移除草稿也移除其照片。旧版仅存在浏览器临时预览的照片无法恢复，可重新导入同一照片为已有草稿补齐。
- 左侧复选框可多选；“全选当前显示的草稿”只选当前筛选可见且尚未启动申请的项；“移除所选草稿 (数量)”逐项移除。处理中的识别任务先停止，已启动/已发送申请不提供勾选，不删除投递历史。某项失败时保留该项，其余项继续。
- 浏览器交互回归验证持久照片预览/缩放、桌面及手机尺寸、多选删除保留已投递项，以及不触发发送。照片数据隔离、删除清理和企业名规范化另有后端检查。

菜单 **二维码投递** → 上传 HR 给的二维码图片 → 确认企业及拟用简历 → **一键投递**。

上传只识别，不发送申请。图片在本机解码。支持 PNG、JPG、WebP、BMP，单张最大 8 MB、2000 万像素。

- **多图选择**：点“添加二维码图片”，一次选择多张照片。
- **粘贴图片**：在二维码窗口按 Ctrl+V；浏览器剪贴板确实提供多张图片时逐张处理。操作系统只提供一张时，请用多图选择。
- **多码照片**：同一张照片里的多个二维码分别加入清单。
- **多链接**：展开已有申请链接入口，每行粘贴一个网址后导入；在输入框外粘贴多行网址也可导入。
- **移除**：每行点“移除”，或“移除所有草稿”。分析中的草稿会先发出停止信号，再移除。已启动的申请保留历史，通过跟踪页查看和停止。
- 同一个已导入网址跳过；一张图片失败不会阻断后面的图片。清单保存在当前档案数据库，关闭窗口或刷新后仍可查看。图片预览仅保留于本次页面会话。

## 先识别真实目标，再匹配材料

企业名称优先读取 JobPosting，再查网页 Organization、招聘页标题、页脚、标志和站点名；招聘软件供应商名不能冒充雇主。显示来源和原文。静态网页不足时，由**平台专用 Chrome 采集器**读取实际渲染内容、iframe 和开放 Shadow DOM。入口上的实际岗位链接会进入岗位选择器，不凭企业行业编造岗位。

招聘总入口、具体岗位和明确的通用人才库分别处理。只有具体岗位且企业、岗位标题、任务齐全，才放开针对岗位的 LM。招聘总入口仍需选择岗位或导入具体岗位网址。页面没有职位链接时应重新读取或提供具体网址，不代表没有招聘岗位。明确的通用人才库只发送所选 CV，不虚构特化 LM。

简历排序比较**各份 CV 的实际文字**和本次岗位标题、任务，展示候选简历的项目原文及对应任务。法英词汇归一、词频权重和标题匹配只提供初始排序；Chrome 深读后可交给已有 ChatGPT 会话作语义比较，模型的 CV 引文和任务引文必须能在本次原文中找到。无可读 CV、无命中或无岗位时不能伪称已经匹配；可手动选 CV。行业猜测仅是次要提示。每项手选 CV 和确认后的企业名保存到该草稿，来回切换或刷新仍保留；重新分析也保留明确手选的 CV。该选择只针对本次申请，不修改全局默认简历。

导入清单不会批量提交。每项分别检查目标和 CV，并单独点击投递；其他项保留待检查状态。

## 点击以后

本次点击授权当前档案、目标页面和所选简历。如果档案已启用动机信，系统通过当前 LM 规则起草和复核信件，再交给已有平台工作进程填写表单并尝试发送。记录为**单次自动材料授权**，不伪称用户已逐字阅读生成的信件。

专用 Chrome 必须可连接。缺失时窗口显示错误和打开 Chrome 按钮。登录、验证码、隐私条款、必填问题或网站不兼容会转为需要用户处理。可接管 Chrome、打开接收方网址、停止任务或继续本次申请；如果页面已关闭，可先通过目标链接重新打开。不会切换到 Edge。

结果必须以网站确认及已有持久回执为准。不确定发送结果时不重复点击发送。已开始请求不会因重复点击再次启动；资料、简历或岗位发生变化时授权失效，需要重新识别和确认。

原有队列和全局自动启动/自动提交选项不受影响。每个候选人的 QR 请求、材料和申请记录分别保存。

## 2026-10-21：导入台交互重构

参考 [Ant Design Upload](https://ant.design/components/upload/) 的受控上传清单、拖放/粘贴、独立文件状态、重试/移除操作。这里只借鉴交互机制，继续使用原生 JavaScript，没有引入 React/Ant 包。Refactoring UI 负责层级、分组、行宽和空态约束。

- 添加入口始终在顶部，不随当前申请详情重建；文件选择后重置输入，可连续选择同一张照片。识别过程中可继续添加下一批，逐项排队读取。
- 左侧是已保存的申请；右侧是当前企业、岗位、简历和进度；底部保留单项发送入口。手机显示横向卡片清单，单项详情继续向下阅读。
- 导入历史逐张保留文件名和排队/识别/成功/重复/失败状态；失败可在原地重试。一个文件失败不会取消后面的文件。导入历史及文件对象仅保留于当前页面会话；成功申请和来源文件名保存在候选人数据库。
- 添加新图片不更换当前选中项，不清空链接输入，也不重建正在编辑的申请表单。源图片在本次会话内用于缩略图；刷新后依然有企业、岗位和文件名可区分。
- 招聘门户有岗位选择器及具体岗位网址输入，确认后通过 `/target` 更新同一张卡，不另建一份申请。保留原始二维码网址、文件名与手选 CV。
- 不再通过“选中一行”隐式启动分析。首次导入需要补充上下文时，仍可由平台 Chrome 深读；继续添加入口保持可用。其他项可主动选择读取。
- 企业名已经在单项标题显示，修改入口折叠；任务和匹配依据按需展开，CV 选择更靠前。完整目标和 CV 未确认前不能发送。
- 列表读取真实申请进度，切到别项仍保留各项状态。申请发送与原队列继续保持独立，导入、过滤、切换、预览不发送申请。

测试补充：在第一张识别请求未完成时继续添加第二张、链接文本不丢失、文件选择节点不替换、失败重试、拖放导入、门户选岗仍为原卡片、独立状态列表、添加按钮在手机/桌面可见、用户资料未改变及全程没有投递写操作。
