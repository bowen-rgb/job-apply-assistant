# 第二轮功能保全维护 · 2026-10-23

本轮按 [mattpocock/skills diagnosing-bugs](https://github.com/mattpocock/skills/tree/main/skills/engineering/diagnosing-bugs) 的可复现反馈循环进行：先增加用户交互测试，实际观察失败，再修复并跑完整回归。UI 沿用项目原生 HTML/JS/CSS、现有字体和主题；依照既定 Refactoring UI 参考检查信息层级、分组与桌面/手机渲染。

## 旧版核对

对比 `42c8963`（桌面端前）、`9751e5e`（排版调整前后）、`875b03c`（新手引导）、`0207c0f`（队列接管）的静态按钮、输入和选择器 ID：原入口均仍在当前页面。app.js 的命名处理函数也未消失。因此本轮没有把“代码仍存在”当成功能正常，继续检查实际可见性和交互。

| 功能 | 本轮发现与处理 | 验证 |
|---|---|---|
| 扫描和 ChatGPT 批量复核 | 保留侧栏扫描、队列复核及其范围选择，没有新增另一套请求逻辑 | 简洁模式、手机、跨客户端状态及现有服务请求测试 |
| 岗位全部状态筛选 | 以前主要依赖侧栏；在岗位正文增加完整下拉选择，标签来自同一组原按钮，原侧栏保留 | 手机切换已略过、语言切换、卡片对应测试 |
| 历史来源筛选 | 停用来源即从选项消失，已有岗位难以查找；现在保留有历史岗位的来源及未登记来源 | 停用来源、选中状态刷新、接口异常测试 |
| 导出人工核验 | 未投递导出错误地使用待人工复核数量，可能错误禁用；按对应范围分别计算。补正文快捷入口 | 未经 AI 复核的可投岗位也能导出、按钮展开面板测试 |
| 岗位依据与动机信 | 数据变化整块重绘时收起；按岗位与详情标题恢复展开状态 | 实际改变分数后刷新、信件重新显示测试 |
| 队列历史与失败详情 | 队列轮询重绘使历史收起；恢复展开状态并按当前岗位隔离 | 队列刷新后保持历史；既有失败详情测试 |
| 来源设置和环境检查 | 入口集中侧栏或资料长表单；补正文快捷入口，复用既有操作 | 跳转配置定位、环境检查无投递写操作测试 |
| 批量准备、下一份、停止、清理、加入队列 | 保持原有队列按钮及处理器 | 简洁模式可见性、既有队列服务测试 |
| 多人档案、二维码导入/删除/放大、资料、Gmail、材料确认 | 不改其流程 | 由既有完整回归检查覆盖；不代表真实第三方网站已成功投递 |

新测试：`tests/test_workflow_parity_ui.py`。初始五个场景全部实际失败，修复后通过；另加入来源异常、信件、配置与原队列入口场景。完整回归还发现 768 像素布局溢出并补上平板两列布局；词汇比对发现“Recherche”在原界面表示科研机构，因此新增独立搜索标签，保持原词汇含义。截图使用虚拟候选人与模拟岗位，在 ignored 的 tmp 目录；没有读取或导出用户简历、邮箱或凭据。

本轮不启动真实扫描、不发送申请、不刷新招聘网站。桌面安装包更新到 1.0.6；当前运行的旧安装需安装更新包后才获得本轮界面变化。
