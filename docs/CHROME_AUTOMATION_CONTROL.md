# 平台驱动的 Chrome 自动化

## 本轮范围与原因

修复浏览器启动、连接状态、队列启动和工作进程入口。此前脚本在 Chrome 缺失时会转用 Edge；健康检查未区分浏览器；队列在检查连接之前就进入运行状态。此次将这些入口统一为专用 Chrome，保留原有表单处理引擎。

调用链：队列页面 → `/api/browser`（只检查）或 `/api/browser/start`（用户点击打开 Chrome）→ `browser_control`；启动队列 → `queue_manager.start` → Chrome 连接预检 → 队列线程 → `browser.launch_apply` 再次预检 → `worker_runtime` → `apply_worker`。浏览器打开操作不启动队列、不填表、不提交。

## 使用方式

1. 更新后重新启动求职平台。
2. 在“求职进度与队列”中点击“打开专用 Chrome”。需要时在该窗口登录 ChatGPT；招聘网站登录仍由现有流程处理。
3. 点击“检查 Chrome 连接”。只有本机 Chrome 的控制连接可用时，队列才允许启动。Edge、无头浏览器、远程地址或连接失败会明确阻止启动；不会替换浏览器。
4. 确认档案、简历和申请材料后，再单独启动队列。平台工作进程负责后续自动化，操作人员不应改用另一个浏览器手动代投并称为系统自动化。

默认连接为 `http://127.0.0.1:9222`，仅允许本机 HTTP 地址及明确端口。启动器只寻找 Google Chrome，使用现有 `data/chrome-profile` 专用目录。招聘网站会话继续沿用既有候选人隔离机制。

“Chrome 已连接”只表示浏览器控制接口可用，不代表 ChatGPT 已登录，也不代表招聘网站可顺利投递。后续登录、网站限制、材料检查与提交确认仍按现有工作流执行。

## 本轮验证边界

测试模拟浏览器连接和进程创建，验证 Chrome 专用启动参数、禁止 Edge 回退、断连不领取任务、不增加尝试次数、不创建工作进程，以及前端按钮只触发对应接口。界面测试使用模拟数据，不投递真实岗位。

本轮真实申请已暂停，等待用户修订简历。没有启动新的实际投递，也没有进行真实 Chrome 启动与完整投递验收；此前环境中的浏览器启动操作曾被自动审批阻止。旧后端进程需要重新启动才能加载新接口。
