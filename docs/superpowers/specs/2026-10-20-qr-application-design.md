# 二维码投递窗口

用户已确认：上传图片 → 自动识别申请入口并显示企业、岗位和拟用简历 → 点击“一键投递”，由平台专用 Chrome 执行；无法判断、登录和手机专属扫码才需要处理。原队列保持暂停。

窗口入口常驻菜单。空状态只显示图片上传和简短示例；识别后显示来源链接、企业名称及证据、企业类型（推测时明确标记）、岗位或通用收简历入口、拟用 CV 和理由，可覆盖选择。岗位内容优先于企业行业；通用入口可按明确页面主题推测方向并标注，无方向依据时用综合简历，没有明确依据不得假装知道企业或岗位。多个二维码先选择入口。非网页协议、微信专属、无二维码、损坏图片、过期/拒绝访问分别提示。

一个主按钮启动本次申请。由现有受管工作进程、专用 Chrome、表单引擎和投递回执完成，保持登录/验证码/隐私声明/缺项的接管边界。点击明确授权本次目标、当前档案、指定 CV 和经新 LM 规则复核的自动生成信件；记录为本次自动材料授权，不伪称用户逐字人工读过信件。上下文或文件变化导致授权失效。重复点击不重复投递，结果不明不重发。全局 auto_submit/auto_start_queue 均不改变。

复用候选人隔离、公开页面读取、JobPosting 提取、CV 标签路由、生成信件质量复核、提交检查和持久回执。二维码图片只在本地解码，上传大小及像素受限，不发第三方识别接口。公开链接与重定向检查禁止内网地址。企业名称的来源和行业分类依据必须展示，未识别允许补充姓名，不虚构。

设计参考：用户指定 Refactoring UI 的 component recipes / audit rubric；原生 HTML/JS/CSS，无 Tailwind 或组件库；沿用现有表面/文字/线条/强调色变量。主信息为目标、拟用简历和下一步，技术证据放折叠区。桌面 1280、手机 375 截图验证，对比、分组、空状态、键盘操作和文字状态。

验收：真实生成二维码图片解码；多码/无效/微信/内网拒绝；结构化岗位和普通企业表单分类；简历路由和覆盖；候选人/简历变化、重复点击、Chrome 断连拒绝；本次授权不影响旧队列；LM 提示调用链检查；模拟网站完整执行与回执，不向真实 HR 提交测试。
