# 原生工作流与前端整理（2026-10-31）

目标：吸收 ai-job-search 与 Apply-Pilot 的能力，继续使用本项目的一个后端、候选人存储和专用 Chrome。上游代码与许可映射见 [整合记录](third-party/INTEGRATION.md)。不运行第二个服务，不嵌入它们的应用。

## 结构诊断与改动

技术栈仍是原生 HTML / JavaScript / CSS，无 Tailwind 或新增组件库。沿用 Endfield 的炭黑、黄色、灰白变量和安洁莉娜资源。参考用户指定的 [Refactoring UI](https://github.com/edisonmbli/refactoring-ui-skill/blob/main/skills/refactoring-ui/SKILL.md) 及其 audit rubric。

| 问题 | 参考规则 | 调整 |
| --- | --- | --- |
| 队列同时承担任务生成、模板、模型配置、邮件和投递，目的不清 | §2.1、§2.8 | 分成岗位、申请队列、反馈与跟进、材料与助手；顶部直接切换 |
| 多层折叠把新增能力藏起来 | §3.6、§8.4 | 助手独立页面，四个明确分类；准备任务提供快捷选择和下一步说明 |
| 简单模式改变可见性与引导层级，造成不同用户看到不同入口 | §2.1 | 删除模式与切换按钮；保留独立的新手分步流程和可展开练习 |
| 隐藏区域的导航只滚动而不打开容器 | 功能缺陷 | 跳转前打开目标祖先 details；跨弹窗导航先关闭旧窗口 |

最终由自动浏览器在 1280 和 375 宽度、中法界面渲染并检查截图；菜单、筛选、工具表单和真实 API 路由继续共用原实现。

## 页面职责与保留能力

- 岗位：原扫描、来源、筛选、AI 复核及人工确认、收藏和导出保持原入口。
- 申请队列：原批量复核、准备队列、执行进度、接管和申请状态看板保留。
- 反馈与跟进：招聘邮件证据、确认更新、跟进提醒、申请结果筛选、账本导入导出和评分规则。
- 材料与助手：准备申请；材料与简历；来源与连接；数据与检查。原 14 种任务、模型、模板、来源、Gmail、Notion、写作、薪资、账本、归档和重置能力全部保留。

切换工具分类不会重建表单。打开页面、轮盘或快捷任务只导航／配置，不启动扫描或发送申请。点击任务的“开始”后才执行。

## 结果真实性

重新核对上游 `Apply-Pilot/src/events.mjs` 和 `ai-job-search/.claude/commands/outcome.md` 后，补齐独立的 `no_response` 状态及旧账本兼容。只有人工确认且填写原因，才能结束未回复申请的跟进；不按沉默时间自动判断，更不标为被拒。队列、接管、再次投递检查、归档、邮件状态冲突检查和跟进提醒均认识这个终结状态。

明确拒信继续沿用完整邮件正文、唯一岗位关联、证据预览及确认事务。抓取失败、准备失败和不建议投递都不属于招聘方拒绝。

## 验证边界

合成候选人、临时数据库、固定来源样本和假邮件／模型返回用于回归。不会发送真实申请、邮件或 Notion 写入；账号是否可用需用户本机连接检查。安装包是独立快照，更新源码不会自动覆盖正在运行的旧桌面应用。

本轮最终隔离存储回归：387 项全部通过；桌面宿主检查：6 项通过。菜单 20 个入口、新旧本机模式偏好、工具分类、中法语言、1280／375 宽度、拒绝与未回复分流均已覆盖。包内独立 Python 的新页面、静态文件、工具／反馈接口和 `no_response` 合约检查通过。
