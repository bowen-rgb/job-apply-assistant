# 从参考到可落地界面

把参考案例拆解成适合当前业务的设计决定，并落实到可运行页面。用户的品牌、任务和已有设计系统优先；示例数值是起点。

## 先理解实际页面

查看真实界面和最终生效的组件、样式、响应式规则。指出用户进入页面后最重要的一件事、主要操作和次要信息。已有页面先修阅读顺序、密度和分组，再决定装饰和动效。记录影响实现的少量设计决定到项目已有设计文档；只有项目没有对应文档时再创建。

用户要求“在上一版基础上改”时，先记录并保留识别特征：配色、标题表达、插画、几何/边框语言和有意的密度。规范化只作用于具体缺陷；数字尺度不要求覆盖品牌标题。删掉插画、改换强调色或把硬边改成圆角，属于风格替换，不能作为普通优化顺带实施。用同一页面的前后对照确认特色还在。

## 拆解参考

从用户提供的案例提取：文字层级、网格与对齐、留白节奏、信息分组、表面/色彩角色、操作反馈。每项决定说明它如何帮助当前任务。采用新的业务内容和现有品牌表达，不把参考页面的栏目、素材或事实直接当成本项目需求。

需要查验项目时，读实现而不只看 README。区分已验证源码、作者声明、截图观察和自己的推断。保存可复查的文件链接与版本；如果参考已随用户提供，可先据其内容工作。

完整拆解用户列举的交互，分别说明“本次实现、当前已有、缺少适用场景”。优先补齐能改善现有任务的细节，不按固定数量挑选；引入新业务能力则依据用户范围决定。

## 建立小型规范

优先复用已有令牌；现有数值混乱时收拢为唯一的颜色、排版、间距和动效来源，逐个接管本次涉及的组件。

| 角色 | 默认起点 |
| --- | --- |
| 大标题/关键数字 | 32px |
| 页面或分区标题 | 24px |
| 内容标题 | 18px |
| 普通正文/输入 | 16px |
| 说明/次级事实 | 14px |
| 简短标签 | 12px |

标题行高 1.2–1.3，正文行高 1.5–1.6。角色和层级比固定像素重要：桌面主页面可用 32px，手机可用 24px；密集表格可用 14px，关键提示保持易读。已有成熟排版体系时在其范围内调整。

布局默认使用 8/16/24/32/40/48px：小分组 8，内容间 16，内边距 24，模块间 32。手机左右边距统一 16px，桌面按容器调整。4px 微间距、1px 边框、图标尺寸及必要光学校正允许偏离网格；8 的倍数是节奏工具，不是行业硬性标准。

表面用背景、内容、次级分组、浮层形成少量清晰层次。一个主操作使用最强强调，其他操作降低权重；状态色始终带文字含义。先用邻近和留白分组，再决定是否需要容器。使用项目现有图标体系。

## 实现与交互

让内容决定高度。长文本可换行，需要截断时提供查看全文方式。手机导航支持明确的展开/收起，表单随可用宽度减列；主要操作容易找到。键盘顺序与阅读顺序一致。

控件覆盖加载、成功、空态、失败、禁用。错误给出恢复方式；批准、发送、删除等操作的结果和边界保持准确。触控目标默认至少 44px，焦点可见，正常正文对比度至少 4.5:1。

动效用于解释状态和空间关系。已有原生能力足够时沿用；按业务需要决定是否增加依赖。关于滚动边缘、弹簧、自动跟随、输入法、图片缩放或音频，按需阅读 [交互模式参考](references/interaction-patterns.md)。不相关的参考能力可以明确留作后续场景。

## 有界验证

完成一轮实现后，在同一批检查桌面和手机、真实或清楚标注的样例内容、中文及较长翻译、空态/错误态、键盘和减少动态效果。重点看阅读层级、横向溢出、重叠、点击目标和滚动位置；有条件时加入 200% 缩放检查。先整理缺陷再集中修复，最多再确认一轮，避免无止境微调。

变更涉及流程或交互语义时补行为验证；纯视觉数值无需编写逐值匹配测试。交付可运行页面、少量前后对照证据、设计规范位置和仍未验证的限制。练习可以临摹，发布时使用适合产品的原创内容，并遵守引用素材和代码的许可。
